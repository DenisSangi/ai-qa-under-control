# FIXES — review findings applied to the suite

Oracle: `docs/spec/SPEC.md`. Input: `review/findings.json` (74 findings, 17 protected tests).

**Result: 73 findings fixed, 1 not fixed** (F-15a985d1e9: it contradicts the specification, see its row).

Paths: `tests/` = `api-tests/src/test/java/com/arcade/qa/tests/`, `support/` = `api-tests/src/test/java/com/arcade/qa/support/`.

Several findings shared one cause and were fixed once:

- **32 × CHK-5 H1** ("baseline taken before the setup's own events arrived"): new `Snapshot.afterEvents(p, playerEvents, gameEvents)` in support, used at every affected baseline with the counts of the setup's own events. The same cause was also fixed at the unflagged baseline of `DepositLimitCountingTest#depositAgainstLimit`.
- **"exactly one event"** (F-3accb696c5, F-4210ad84c4, F-e7f2e93d1b): new `Events.awaitOnly`.
- **"`details` names the field"** (F-d6efec337c, secondary of F-89cbe10939): `Asserts.assertDetailsMention` made exact.
- **JSON types and representations the spec does not fix** (F-dbb8ab80fa, F-293c1b4bf2, F-e74aabfae0, F-533c02dce4): `Json.instant`, `TestClock.offset()`, relaxed `assertTopFormat`.
- **order of the limit list** (F-c4d0e7d6ef, F-276ffe33a7): one `assertLimitsUnchanged` in `DepositLimitsTest`, also used in CL-018.
